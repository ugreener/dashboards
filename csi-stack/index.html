A specification is a contract, not software

It is a written agreement about which calls exist and what they mean. Kubernetes and a storage product can work together without either team writing custom code, because both sides answer the same calls.

A driver is a translator

The driver is the software that turns those standard calls into commands one storage product understands. One driver per product: PowerStore has one, Ceph has another. Kubernetes picks the driver from the storage class that created the volume.

A sidecar is a helper in the same pod

A pod is the smallest unit Kubernetes runs, and it can hold more than one container. A sidecar is a second container in the driver's own pod that adds a capability, here the newer replication calls, without the driver image having to change.

Three lab words used below. A VSA is one virtual storage array: two virtual machines that act as one appliance. A spoke is one OpenShift cluster and its site. The hub is the central cluster that coordinates the spokes.

The picture has four layers, numbered on the diagram: the two contracts at the top, the Kubernetes software that issues requests, the drivers that translate them, and the storage systems that hold the bytes. 1 · The two contracts
Contract · open industry standard
CSI specification
The agreed list of calls between Kubernetes and any storage system: create, attach, mount, snapshot, delete.
Contract · separate community project
CSI-Addons specification
The second contract. It adds what CSI never defined: replication, volume groups, reclaim space, network fencing, key rotation.

Follow one request

The same six handoffs every time a volume is protected, promoted or resynced.

1

Ramen writes the request

Ramen decides a disk needs protecting or needs to move, and creates a VolumeReplication or VolumeGroupReplication object. It does not call any storage system.

2

The controller picks the driver

The csi-addons controller sees the new object, reads which volume it names, and works out which storage driver owns that volume.

3

It finds that driver's sidecar

Each sidecar publishes a CSIAddonsNode record, so the controller knows how to reach it and which operations the driver supports.

4

The sidecar forwards the call

The controller sends one gRPC call, a fast remote procedure call of the same kind the CSI standard uses. The sidecar passes it to its own driver over the driver's local socket, inside the same pod.

5

The driver talks to the array

For PowerStore: enable replication, promote the copy, demote the old side, or resync. The array does the actual copying on its own schedule.

6

The answer goes back up

The controller writes the result into the object's status. Ramen reads that status and decides the next step of the recovery.
